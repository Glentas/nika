# ЛР №2 без Wit.ai: классификация сообщений логическими правилами

Каталог `classification/` — результат лабораторной работы №2 для предметной области
«Конфуцианство». Внешний сервис Wit.ai **не используется**.

## Почему это работает

В системе NIKA зарегистрированы **два** агента классификации темы сообщения
(`problem-solver/cxx/messageClassificationModule/MessageClassificationModule.cpp`):

| Класс действия | Агент | Средство классификации |
|---|---|---|
| `action_message_topic_classification` | `MessageTopicClassificationAgent` | Wit.ai (`WitAiClient`) |
| `action_alternative_message_topic_classification` | `AlternativeMessageTopicClassificationAgent` | **логический вывод SCL-machine по правилам класса `concept_classify_message_rule`** |

Оба действия входят в программу `message_processing_program`, которую интерпретирует
`MessageReplyAgent` на каждую реплику пользователя
(`problem-solver/cxx/messageReplyModule/agent/MessageReplyAgent.cpp`). Если вывод по
правилам непустой — сообщение классифицировано; иначе оно попадает в класс
`concept_not_classified_by_intent_message`.

Правила ответа и фразы для вопросов «Что такое …?» и «Каким бывает …?» **уже есть**
в базе знаний NIKA и являются универсальными:

- `logic_rules/lr_message_about_entity/lr_message_about_entity.gwf` — правило ответа;
- `subject_domain_of_phrases/examples/concept_phrase_about_entity/concept_phrase_about_entity.gwf` — фразы;
- `logic_rules/lr_message_about_subdividing/lr_message_about_subdividing.gwf` — правило ответа о разбиении;
- `subject_domain_of_phrases/examples/concept_phrase_about_subdividing/concept_phrase_about_subdividing.gwf` — фразы.

Дописывать нужно было только **правила классификации** — они и лежат в этом каталоге.

## Состав каталога

| Файлы | Кол-во | Назначение |
|---|---|---|
| `lr_classify_what_is_<сущность>_message.gwf` | 43 | «Что такое …?» / «Кто такой …?» / «Что означает …?» |
| `lr_classify_<класс>_subdividing_message.gwf` | 8 | «Каким бывает …?», «На что разбивается …?», «На что декомпозируется …?» |
| `definitions.scs` | 1 | связки `nrel_definition` для понятий (см. ниже) |
| `utterances.json` | 1 | перечень обучающих формулировок в формате экспорта Wit.ai |

Все 51 правило получены **точечной подменой идентификаторов и содержимого sc-ссылок**
в рабочих файлах NIKA `lr_message_about_entity.gwf` и `lr_subdividing_message.gwf`:
топология, типы узлов и дуг не изменены, поэтому формат GWF гарантированно принимается
и KBE, и сборщиком базы знаний. Генератор — `tools/gen_lr2.py`.

`utterances.json` собран вручную и заменяет экспорт из Wit.ai, который требуют
методические указания положить в `kb/extra/{папка предметной области}/classification/`.
Структура приведена к формату экспорта Wit.ai (`intents` / `entities` / `utterances`),
содержит 110 эталонных формулировок.

## Главное ограничение: полное совпадение строки

Сопоставление текста сообщения с эталонной sc-ссылкой правила выполняется
**посимвольным сравнением**, а не поиском подстроки:

```cpp
// scl-machine: TemplateSearcherAbstract::isContentIdentical
if (contentMap.second != linkContent) { result = false; break; }
```

Правило срабатывает, только если текст в диалоговом окне совпадает с содержимым
эталонной ссылки **полностью**, включая знак вопроса, регистр и пробелы.
Поэтому на каждую формулировку вопроса нужна своя эталонная ссылка — в каждом
правиле их две или три, объединённые отношением `nrel_disjunction`.

Если Ника не отвечает на вопрос, первым делом следует сравнить введённый текст
с содержимым ссылки в соответствующем `.gwf` (открывается в KBE или текстовым
редактором — содержимое лежит в `<![CDATA[...]]>`).

## Зачем нужен `definitions.scs`

Фраза ответа `concept_phrase_about_entity` строится по двум шаблонам:

```
${_entity_note_name} - ${_note}.
${_entity_definition_name} - ${_definition}.
```

Первый шаблон использует `nrel_main_idtf` и `nrel_note`, второй — `nrel_main_idtf` и
`nrel_definition`. В фрагменте базы знаний определения понятий хранятся каноническим
для Технологии OSTIS способом (структура в роли `rrel_key_sc_element`, принадлежащая
классу `definition`, со ссылкой-примером через `nrel_sc_text_translation`), поэтому
второй шаблон не сработал бы. Файл `definitions.scs` добавляет плоские связки
`nrel_definition` для 11 понятий, на которые обучен классификатор, — после этого
Ника отвечает и примечанием, и определением. Отношение `nrel_definition` определено
в `kb/non_subject_domain_concepts/nrel_definition.scs` и здесь не переопределяется.

Экземпляры (Чжу Си, жэнь, Лунь юй и др.) отвечают по первому шаблону — примечанием.

## Порядок выполнения

```bash
cd nika && git checkout tpis-2023
cp -r <этот каталог> kb/extra/section_subject_domain_of_confucianism/classification/
./scripts/build_kb.sh                     # или: docker compose run --rm problem-solver build
./scripts/run_sc_server.sh                # терминал 1
./scripts/run_sc_web.sh                   # терминал 2
./scripts/run_interface.sh                # терминал 3  -> localhost:3033
```

Переменная `server_token` в секции `[wit-ai]` файла `nika.ini` при этом не используется:
агент Wit.ai не находит сущность и завершает действие с ошибкой, после чего программа
обработки сообщения переходит к альтернативной классификации.

Отключать агента Wit.ai через
```
action_deactivated -> action_message_topic_classification;;
```
**не рекомендуется**: механизм существует (`ActionUtils::isActionDeactivated` проверяет
именно эту дугу при инициализации модуля), но действие останется инициированным и
незавершённым, что может привести к ожиданию таймаута на каждой реплике.

## Проверка в sc-web

После сборки в sc-web (`localhost:8000`) находятся:

- `lr_classify_what_is_concept_confucianism_message` — правило, его принадлежность
  классам `concept_classify_message_rule_priority_1` и связка `rrel_main_key_sc_element`
  с дугой импликации;
- `if_what_concept_confucianism` — структура условия, принадлежащая классам
  `concept_template_with_links` и `atomic_logical_formula`, с эталонной ссылкой
  `Что такое конфуцианство?`;
- `concept_message_about_entity` — пополненный класс сообщений.

## Как расширить

Список сущностей задаётся в `tools/gen_lr2.py` в списке `ENTITIES`
(пара «идентификатор — тип»: `person` даёт вторую формулировку «Кто такой …?»,
остальные — «Что означает …?»). Правила о разбиении генерируются автоматически для
всех классов, у которых в базе знаний задано `nrel_subdividing`.

```bash
python3 tools/gen_lr2.py
```

Сейчас обучено 43 сущности и 8 разбиваемых классов — 110 эталонных формулировок.
Чтобы обучить классификатор на все 49 экземпляров, помеченных в ЛР №1 классом
`concept_wit_entity`, достаточно перенести их в `ENTITIES`.
